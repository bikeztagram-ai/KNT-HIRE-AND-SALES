# KNT product UX rules

## Primary principle
KNT should reduce engineer admin rather than force engineers to learn a new paperwork process.

## Jobsheet entry modes
Every new job supports three routes:

1. **Scan paper** — photograph the existing handwritten KNT sheet. Keep the original image as the source document; extract a structured, editable copy.
2. **Voice** — speak naturally. Convert speech into structured job fields and show the engineer the result before saving.
3. **Type** — use a conventional digital form when that is fastest or when precise entry is needed.

AI extraction is assistive, never authoritative. Uncertain OCR/handwriting or speech values must be visible for confirmation.

## Source evidence
Original jobsheet photos, job photos, supplier paperwork, certificates and signatures belong to the relevant job/forklift record. They must not exist only in a device gallery.

## Help system
Every important screen has contextual help. Help should explain:
- what the screen is for;
- what can be done here;
- what the important buttons do;
- what KNT will and will not do automatically.

A central **How to use KNT** guide should remain available from More. Contextual help should be progressively shortened as the user becomes familiar with the system, without removing access to full guidance.

## Engineer-first interaction
- Large touch targets.
- Minimal typing.
- One-hand-friendly mobile layout.
- Fast search by job number, customer, plant number, serial number and machine.
- Clear status and due-date warnings.
- Drafts should be recoverable after interruption.
- Never silently discard source evidence.
- Customer-facing actions such as invoice sending require an explicit human action.

## Selected visual direction
Use the card-style direction (layout 4) as the baseline: clean white cards, dark navy shell, KNT blue accents, compact status cards, simple bottom navigation on mobile and a sidebar-style expansion on desktop.
