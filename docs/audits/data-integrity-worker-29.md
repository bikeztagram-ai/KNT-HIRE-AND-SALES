# KNT data integrity audit\n\n## Scope\nReviewed the current operational schema for safe V1 hardening opportunities.\n\n## Findings\n- Core entities have primary keys and the main operational relationships use foreign keys.\n- Useful indexes exist for jobs by forklift/date, job evidence, job parts, supplier order lines, invoices and reminders.\n- Operational status fields remain text values in several workflows; the application currently owns the allowed lifecycle values.\n- Authenticated RLS currently permits shared operational access; role-aware restrictions remain a separate security/product decision.\n\n## Decision\nNo destructive or speculative schema constraint was added in this worker. Further hardening should be tested against a disposable Supabase instance before production migration.\n
